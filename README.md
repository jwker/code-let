# Codelet

内嵌 [Pi](https://www.npmjs.com/package/@earendil-works/pi-coding-agent) SDK 的桌面编码代理宿主。

Pi 是一个能在终端里读写代码、执行命令的编码代理。Codelet 把它装进一个桌面应用：多标签、多项目、
文件预览、可中断的对话 —— 用的是 Pi 自己的会话文件、凭据和扩展，不是另起一套。

## 功能

**标签是项目。** 顶部一个标签就是一个项目。每个项目标签记住自己的入口（代码 / 文档 / 浏览器 /
某个 agent / 设置）、当前活动的 agent、区域 5 的宽度 —— 切走再切回来还是原样。
**关标签只是收起页面**，不中止那个项目里任何正在跑的 agent。

**窄轨 + 两列。** 左边 56px 的窄轨分三段：项目功能（代码、文档、浏览器）、agent 列表（只有这段滚动）、
项目设置（钉底）。右边是**可选**的区域 5 和**必填**的区域 6：
代码是「文件树 + 预览」、文档是「文档树 + 预览」、浏览器和 agent 只占区域 6、
产品 agent 是「窄对话 + 它自己的浏览器」。右侧检视器已经退场。

**一个 agent 就是一个会话。** 头像就是会话列表。每个 agent 有自己的类型（基础 / 开发 / 产品，
外加用户自定义的）、名字、会话文件，桌面上独立跑一套 runtime —— 点别的 agent 不会打断它。
同一类型可以有多个实例，右下角角标是实例序号。

**类型与提示词。** 类型决定名字、头像颜色和一段提示词。内置三个的名字、说明、颜色由应用提供，
只有提示词能改；全局设置里可以新增「自定义 agent」（名字、说明、颜色、提示词）。提示词在
**会话启动**时追加到系统提示末尾 —— 改完已开的会话不受影响，新建或 `/reload` 之后才生效。
产品 agent 还有一段程序生成的原型规则（原型目录 + `data-block`），排在用户提示词之后，不可编辑。

**两个名字，分开维护。** *agent 名*是窄轨里的显示名（右键 → 重命名），*会话名*写进 Pi 的会话文件
（输入框 `/rename`、项目设置里改名、裸 pi 里的 `/rename`）。它们**互不同步**：改 agent 名不写会话文件，
改会话名也不动 agent 名。窄轨的悬停气泡两行显示，第二行小字是会话名。

**归档。** 头像右键 → 归档：会话文件原地不动，只是从窄轨里收起来；项目设置 → 归档的 agent 里能
恢复或删除。超过设定天数没活动的**基础** agent 会自动归档（应用级设置里改天数，填 0 关闭）；
自定义 agent 跟开发、产品一样不参与自动归档。

**会话管理。** 项目设置里列出这个项目的全部会话，不管有没有被 agent 管着。没有 agent 的可以导入
（给它建一个基础 agent，会话文件不动）；每条都能改名（改会话名）和删除（移到废纸篓）。

**项目清单。** 存在应用数据目录里。移除项目只是从清单里去掉，Pi 的会话文件一个字节都不动。

**新建 agent 先选类型和名字。** 三个入口（窄轨的「＋」、输入框的 `/new`、项目设置 → 会话管理）
打开同一个对话框：上面是类型卡片（两列网格，超过 6 个可滚动；内置三个在前，自定义在后），
下面填名字。名字预填「类型名 + 本项目该类型下一个序号」并处于选中状态，直接回车就建。
**类型建完不能改** —— 它决定区域 5/6 怎么分派，要换形态就新建一个。名字只写 `agents.json`，不写会话文件。

**删除对话。** 项目设置 → 会话管理里逐条删（批量删除暂不做）。
会话文件移到系统废纸篓（可恢复），管着它的 agent 一起从窄轨消失，正在跑的那一轮先中止。

**重命名会话。** 项目设置 → 会话管理里点「改名」，或者输入框执行 `/rename`（会把你送到那一页）。
回车保存、`Esc` 取消，
留空恢复默认标题（首条消息）。名字写进 Pi 的会话文件，跟 Pi 自己改的名是同一处 ——
**它不影响窄轨里的 agent 名**。

**项目内扩展。** `ext/` 里的扩展由 `npm run build:ext` 编译到 `out/ext`，主进程把它交给 Pi 加载；
注册的命令会出现在 `/` 菜单里；加载/执行失败会显示在主区顶部的提示条。
自带一个 `/repo-status` 示例（读 `git status`，结果作为扩展消息显示）。

**扩展消息。** 扩展用 `pi.sendMessage()` 发出的自定义消息会显示在对话里（带 `[customType]` 标签）；
`display: false` 的消息和扩展状态 entry 不显示。扩展注册的 TUI renderer 用不了，Codelet 统一走通用样式。

**输入框的 `/` 与 `@`。** `/` 在消息开头拉起命令面板：新建对话、切模型、重命名、压缩、重新加载、停止、
设置思考等级，以及 Pi 的 prompt 模板、扩展命令、技能命令。扩展命令可以在生成中执行；
模板和技能等这一轮结束。扩展命令提供 `getArgumentCompletions` 时，输入 `/name ` 会继续列出参数候选；
`/thinking` 用同一套参数菜单选择当前模型的可用等级，底部状态栏显示 `think <level>`。
`@` 选文件：路径插进正文，同时作为内容附件发送（文本包成 `<file>` 块，图片走
`PromptOptions.images`），带单文件和总量上限；chip 显示大小与估算 token，并和正文里的
`@path` 双向同步；PNG/JPEG 发送前按最长边 1568 缩放。搜索尊重 `.gitignore`，按项目缓存索引，
查询切换时会取消旧请求。输入框的回形针可以打开系统文件选择器，多选项目外的文件和图片；
绝对路径只留在主进程，发送时回传选择器签发的附件 id。发出去的图片会在用户消息里显示为缩略图；
原图只给模型，不进入实时事件流。

**临时对话。** 输入框执行 `/ask` 打开一个临时窗口，继承当前项目的 cwd 和模型；可以连续聊天、
从回形针上传附件、切换模型，但不解析 `/` 命令和 `@` 引用。窗口可以最小化成右下角胶囊继续使用；
只有点 `×` 并二次确认后才彻底关闭。临时会话使用 Pi 的内存 session，不写会话文件、也不进窄轨。

**对话导航。** 普通和终端模式下，对话区左侧有一列固定的圆点，每条用户输入一个点；
悬停展开输入摘要，点击滚到对应轮次，当前轮次跟随滚动高亮。圆点间距固定，不随对话长短变化；
少于两条用户消息时不显示。

**对话区三种排版。** 普通（Markdown）、终端（ANSI）、HTML。前两种读同一份内容流。

**一轮对话分主次。** 一条用户消息之后的几十条助手消息和工具调用会折叠成一行「过程」，
生成中也保持折叠，折叠行里的工具次数和段落数实时更新；最终答案单独顶格。
生成期间只显示「思考中」和走过的秒数，所有循环结束后才显示复制、输出 token、缓存和耗时。

**模型请求失败会明确提示。** provider 返回额度不足、鉴权失败、限流或网络错误时，
对话里会出现一条危险色提示，显示分类后的标题和原始错误；不会只留一个空回复。

**随时叫停。** 发送按钮在生成中变成停止方块，`Esc` 同效。已经生成的内容会保留并标「已中止」。

**浏览器。** 窄轨的「浏览器」入口占区域 6：多标签、地址栏、前进后退和刷新，页面用独立
`WebContentsView` 渲染。v1 只打开本地页面和明确的协议（`http/https` localhost、`file:`、
`data:`、`javascript:`、`about:blank`），不把外网站点塞进应用。

浏览器有**两个宿主**：项目级（窄轨入口）和 agent 级（产品 agent 的区域 6）。两套标签池互不相通 ——
agent 的 `browser_tabs`、`browser_open`、`browser_navigate`、`browser_snapshot`、`browser_click`、
`browser_type` 只作用于**它自己**那一套，碰不到你在项目浏览器里看的页面。地址校验仍然在主进程做。

**代码区。** 区域 5 是文件树，分「文件 / 改动」两个 tab；改动里显示当前分支、上游、ahead/behind，
按已暂存、未暂存、未跟踪、冲突分组列出文件。点一个文件，区域 6 换成它的 diff（相对 HEAD 或
相对 index），`Esc` 或 ← 回到文件预览。只读：不提供 stage、commit、discard、stash。
状态来自本机 `git status --porcelain=v2`，diff 按文件按需读取；切项目、窗口聚焦、agent 结束
和手动刷新时更新。不是 Git 仓库的目录显示明确空态。

**文件预览。** 区域 5 的文件树按当前项目根展开；区域 6 预览 Markdown、图片、HTML（沙箱 iframe）、
代码（Shiki 高亮）和纯文本。指向项目**外**的符号链接（`node_modules` 里的 link 依赖很常见）
不会被展开，那一行会写明原因。

**文档区。** 区域 5 列出 `AGENTS.md` 和 `.ai/` 下每个目录（组不是写死的，新加一个
`.ai/artifacts` 也会出现），区域 6 渲染选中的那一篇。第一版**只读** —— 写文档走对话。

**模型切换。** 每个会话可以单独选模型，切换写进会话文件；也可以设为新会话的默认。

**外部改动检测。** 会话文件在别处被改过时，标签会标记为「需要重新加载」并暂时锁住输入 ——
避免用旧上下文覆盖别处写入的内容。

**设置窗口（应用级）。** 标题栏「更多」菜单里的「设置」打开一个独立窗口。
设置项本身是一份注册表（`contract/settings.ts`）—— 加一项就是加一条数据，页面结构不动。
分类：Agent（自动归档天数、归档后保留）、agent 类型（内置三个的提示词 + 自定义 agent 的增删改）、
调试（记录开关、占用、上限、清空）、大模型。窗口默认 1200×820（最小 960×600）—— agent 类型那一页是
左右两栏（240 列表 + 编辑区），窄了放不下。窗口默认停在第一个有内容的分类上 —— 不然打开就是一页空白。

**项目设置（项目级）。** 窄轨底部的入口，区域 5 是分类、区域 6 是内容：
归档的 agent（恢复 / 重命名 / 删除）、会话管理（导入 / 改名 / 删除）、通用（应用级的归档天数、
打开控制台窗口）、项目（路径、移除项目）。每个分类右上角都标了它管到哪儿 ——
应用级和项目级混在一列里最容易误会。

**调试控制台（独立窗口）。** 不是主窗口里的一个面板 —— 从项目设置 → 通用，或设置窗口 → 调试打开。
之所以是独立窗口：排查问题时要跟主窗口并排看，塞进主窗口只会把正在看的东西挤掉。
窗口只有一个实例，再点一次只是聚焦。它把每次模型请求的上下文留档：
Pi 侧的 transcript、provider 侧的原始 payload、provider 的响应，分成四页签。
内容按需取 —— 索引里存着骨架，展开一级节点不用等，点某一条消息才去读那一条的正文。
列表里能勾选多条，导出和删除都在列表页做（都带二次确认）。
列表里每行是一次请求：时间、这是该会话的第几次请求、触发这次请求的那句话、耗时、状态码；
会话名只在列表跨多个会话时才显示。
窗口标题是「调试控制台」，可以独立移动、最小化；关掉不丢记录，重开还在。

**窗口标题与 Dock 菜单。** 三个窗口各有各的标题：主窗口「Codelet」、设置窗口「设置」、
控制台窗口「调试控制台」—— 红绿灯旁边显示的就是它。右键点 Dock 图标，菜单里按标题列出
当前打开的窗口，点一个直接切过去。
记录存在应用数据目录，一次请求一个容器文件加一个索引文件；图片抽成 blob，
正文里只留引用。不自动删除：删不删由人决定；要归档就在界面上导出 ——
单条、勾选的多条、多个会话、全部，导出成一个 zip（容器、索引、manifest、图片成套）。
记录开关在设置里，打开即生效，不用重启会话。

## 快速开始

```bash
npm install
npm run dev
```

首次启动会在系统应用数据目录里创建配置文件。Pi 的凭据默认读 `~/.pi/agent/`，
所以在终端里 `pi` 登录过的账号可以直接用。

## 架构

```
host/
├── main/        主进程：Pi SDK 封装、权威状态、IPC、文件读取
├── preload/     contextBridge（必须是 CJS）
└── renderer/    React + Zustand（含浏览器预览用的假宿主）
contract/        主进程与渲染进程共享的纯类型、IPC 规格、事件折叠逻辑
tests/           vitest（不启动 Electron）
build/           应用图标（源文件 + 生成产物）
scripts/         图标生成脚本
ext/ view/       预留：Pi 扩展与独立视图组件
```

几条贯穿全局的约定：

**主进程是唯一的数据面。** 渲染进程不碰文件系统、不碰 Pi，一切都过 IPC。
所有 IPC 入参用 zod 校验，事件按 16ms 合并窗口推送，单条载荷上限 256KB。

**事件不是类型化导入的。** 渲染进程用自己的 `{ type, data }` 接 Pi 的事件，
不 import SDK 的事件类型 —— 这样渲染进程不依赖 Pi，能单独构建和测试。

**状态分为「事实」和「怎么显示」。** 主进程只推事实（`refreshing: true`），
「延迟 200ms 才显示、显示了至少停 500ms」这类展示规则全在渲染进程，
可以在没有 Electron 的环境里单测。

## 容易踩的坑

- **Pi 必须外部化。** Pi 的扩展加载器用模块映射把 `@earendil-works/pi-ai` 等包强制解析到
  Pi 自己那份。electron-vite 若把 Pi 打进产物，就会出现两份类实例，`instanceof` 全部失效。
- **Pi 是 ESM-only**，所以主进程也是 ESM（`out/main/index.mjs`）。
- **preload 必须是 CJS**（`sandbox: true`）。
- **`app://` 协议要在 `app.ready` 之前注册**，否则相对路径、`fetch`、ES module 脚本失效。
- **`AgentSessionRuntime.dispose()` 不 await 正在跑的那一轮**。关标签或重建前必须先自己
  `await session.abort()`，否则半截轮次可能没落盘。
- **`switchSession()` 会 abort 当前轮**（内部 `teardownCurrent()`）。这也是为什么每个标签
  用独立 runtime 而不是共享一个。
- **Electron 二进制下载慢**：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install`

## 命令

```bash
npm run dev        # 开发（vite dev server + electron）
npm run build      # 构建到 out/
npm start          # 预览构建产物
npm run typecheck  # 主进程 / 渲染进程两套 tsconfig
npm test           # vitest
npm run test:e2e   # 构建后用 Playwright 启动 Electron 跑 UI 测试
npm run icon       # 重新生成应用图标（需要 Electron）
npm run dist       # 打包（electron-builder，按当前机器架构出 dmg）
npm run dist:mac   # macOS 两种架构都打（arm64 + x64）
```

产物落在 `release/`，名字带上最后一次提交的短 hash，例如
`Codelet-0.1.0-387e7756-arm64.dmg`。工作区有未提交改动时 hash 后面多一个 `-dirty` ——
这种包能装能跑，但它不对应任何一个提交。`npm run dist` 默认只打当前架构，
配置里列的两种架构要靠 `dist:mac` 显式打开（也可以在命令行追 `-- --mac dmg --x64`）。

打包**默认不签名**。要出签名包就用 `CODELET_SIGN=1 npm run dist:mac`，一个架构约两分钟。
签名会给每个被签的文件向 Apple 的时间戳服务打一次网络往返，所以 `electron-builder.yml` 里用
`signIgnore` 跳过了 Electron 自带的 220 个 `locale.pak`（它们是数据文件，仍然被包签名封住）——
不跳过的话一个架构要十几分钟。

签名只能在打包时做，没法提前：签名是对**这一个产物**的内容算的，任何重新打包都会改变文件，
旧签名随之作废。所以只有要分发的包才签；本机自用的包不签，装上去照样双击就开。

## 开发版的数据放在哪

开发版用 `~/Library/Application Support/Codelet Dev`，打包后的应用用
`~/Library/Application Support/codelet` —— 两份数据、两把单实例锁，所以
`/Applications` 里的 Codelet 开着的时候照样能跑 `npm run dev`。

想拿真实数据调试就显式指过去：

```bash
CODELET_USER_DATA="$HOME/Library/Application Support/codelet" npm run dev
```

注意这时两边共用同一份 `agents.json` 和会话文件，别同时开着两个实例往里写。

## 浏览器预览模式

`npm run dev` 之后直接在浏览器打开 `http://localhost:5173` 也能看到完整界面，数据是假的。

渲染层统一从 `host/renderer/src/host.ts` 取宿主能力：`window.codelet` 存在时走 preload，
不存在时回落到 `mock/host.ts` 的假实现。状态栏右下角会显示「浏览器预览 · 假数据」。

这不是产品形态（应用的数据面全在主进程），只是让 UI 迭代能脱离 Electron 单独跑。

模型选择 · 入口与选择器

会话用哪个模型，在哪看、在哪换

这份稿只做一件事：让用户看见当前会话用的是哪个模型，并且能换。对话区、侧栏列表、检视器的既有结构都不动， 新东西是一个入口加一个选择器浮层。

四个入口方案共用同一个选择器，所以先比位置，再定选择器本身的样子。

先摆事实（Pi 侧已核实）

  • 模型是绑在会话上的。会话 jsonl 里有两类条目能确定模型：model_change（新建会话时写一次， 之后每次 setModel() / cycleModel() 追加一条）和助手消息自带的 provider + model。
  • 恢复时读会话，不读全局默认。createAgentSession() 在调用方没显式传 model 时， 用 getBranchSelection(分支) 从分支末尾往前扫，第一个碰到的 model_change 或助手消息决定模型。 所以「某个对话选了某个模型，下次进去保持住」成立。
  • 恢复失败是静默的。如果那条记录里的 provider 现在没有凭据，会退回全局默认，原因只放进 modelFallbackMessage。Codelet 现在把这个字段吃掉了 —— runtime.ts 拿到、往后传， 但没有任何界面显示它。
  • 能拿到的清单是「可用模型」。session.modelRuntime.getAvailableSnapshot() 给已配置凭据的模型， 每个模型带 name / provider / contextWindow / maxTokens / reasoning / cost。不需要另建目录。
  • Codelet 目前没有任何模型界面。host/renderer 里除「模式（mode）」之外不含 model 相关代码， 也没有选模型的 IPC 通道。状态栏只显示项目名、会话 id、模式、事件数、Pi 就绪状态。

这份稿里的四个词

当前模型
当前会话此刻用的模型。跟着会话走，换会话就换。
默认模型
新建会话时用的模型，存在全局设置（~/.pi/agent/settings.json）。setModel(model, { persist: true }) 才会改它。
入口
「看得见当前模型、点了能换」的那个控件 ���— 这份稿比的就是它放哪。
选择器
点入口之后弹出来的浮层。四个入口方案共用同一个选择器。
A

状态栏：右下角一个可点的模型名

状态栏本来就在显示「这个会话是什么状态」，模型属于同一类信息。放这里最省地方， 而且不占主区的任何位置，也不会跟对话内容抢注意力。

选择器本身长什么样

入口定下来之后，浮层是共用的。下面两种形态，差别在「要不要搜索」和「能不能顺手改默认」。

P1 · 推荐

带搜索的分组清单 + 底部一行「设为新会话默认」

按 provider 分组，每项右侧给三个最有用的指标（上下文长度、是否支持思考、输出价格）， 顶部一个搜索框，底部一个「设为新会话默认」勾选框。当前那个打勾。

P2

不带搜索的短清单

只有分组、勾选、模型名。适合「可用模型通常不超过 6 个」的用法，代码量最小。

四个入口放在一起比

按「看不看得见」「有多容易点到」「会不会挤到别的控件」「要动多少东西」四轴排。

入口看得见当前模型点到它挤不挤改动量
A 状态栏是（但 10.5px 小字）要想到去那儿找不挤小
B 输入框是每次说话都看到挤（与发送键抢位置）小
C ⋯ 菜单否（要点两次）点两次不挤最小
D 标题栏是一直可见中（拖动区有坑）中

推荐：A 状态栏显示 + B 输入框入口，共用一个选择器（P1）

两个位置各干一件事，不重复：

  1. 状态栏只做指示：随时能看到当前会话用的是哪个模型，不占主区位置。
  2. 输入框左下角做操作：要换的时候就在这里点，位置就在「准备发消息」的地方。

两处点开的都是同一个 P1 选择器。这样「看得见」和「好点到」两个目标都满足，而且不用在狭窄的输入框行里 塞一个长模型名 —— 输入框那个胶囊只显示简称（M3.1-Flash），完整名字在状态栏和浮层里。

不选 C 的理由：换模型是高频动作，塞进低频菜单里，用户每次都要点两次、而且看不见当前值。 不选 D 的理由：标题栏是拖动区，-webkit-app-region 的坑（D16 记过两条）会让可点元素很脆； 而且标题栏表示「这是哪个会话」，放一个看起来像全局设置的东西容易误解。

要动的东西

渲染进程不 import Pi（边界 1），所以模型清单必须由主进程取好、经 IPC 下来。现有 HostSnapshot 加两项， 再加两个通道。

contract/index.ts interface SessionState { … model: { provider: string; id: string; name: string } | null modelFallback: string | null // 恢复失败的说明，直接上屏 } interface ModelOption { provider: string id: string name: string contextWindow: number reasoning: boolean cost: { input: number; output: number } // 每百万 token } IPC.modelsList = 'host:models:list' // → ModelOption[] + 当前 IPC.modelsSelect = 'host:models:select' // { provider, id, persist } → 新快照

主进程侧只需要三句 Pi 调用：session.modelRuntime.getAvailableSnapshot() 取清单、 session.setModel(model, { persist }) 切换、session.model 读当前。 切换成功后 Pi 会发 model_select 事件（已有透传通道），快照也要跟着推一次。

这一轮不做

项为什么
思考强度（thinking level）切换和模型是两件事，规则也不同（切模型时会重新 clamp）。先只做模型，等这块稳了再说。
会话列表里显示每个会话的模型看着有用，但列表项已经很密；而且模型是「进去之后才关心」的信息。
模型对比 / 成本统计那是会话统计页的事，不是选择器。
在 Codelet 里配置 API key / 登录凭据沿用 ~/.pi/agent（D9），登录仍在 pi 里做。选择器只列已配置的。
按任务自动选模型不可预测，也不可解释。用户自己选。
改终端 / HTML 模式的界面普通模式优先（D14）。这两档这次不动。

怎么算做对了

拿两个都聊过的会话交替切，逐条看。

#标准
1会话 A 选了模型 X、会话 B 选了模型 Y；在 A / B 之间来回切，状态栏与输入框始终显示各自的模型。
2在 A 里换模型，B 不受影响；重启应用后 A 仍是新换的那个。
3勾了「设为新会话默认」再换，新建的会话用新默认；旧会话不变。
4恢复失败时（撤销该 provider 的凭据），状态栏显示警告并说明「未能恢复 X」，而不是静默换成别的。
5清单里只出现已配置凭据的模型；一个都没有时给出可执行的提示。
6生成中入口禁用并说明原因；切换过程中不重复触发。
7主区被压到 160px 时，输入框那一行不出现横向滚动条（收缩顺序：先隐藏「⌘↵ 发送」，再缩模型简称）。
8亮暗两套主题下浮层、勾选、价格数字都读得清。

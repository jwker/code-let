对话区 · 回到顶部 / 回到底部

四个局部方案，都按同一套状态规则来：两个按钮不会每刻同时出现。图里每个小框是主区右下角的 1:1 裁切（内容列 720、右侧留白 50、输入卡圆角 18），虚线是内容列边界，真实界面里没有。

共用的状态规则

  • 内容不满一屏（scrollHeight ≤ clientHeight）：两个都不显示。
  • 在顶部（scrollTop ≤ 8）：只需要「回到底部」。
  • 在底部（离底 < 80px，跟现有 PIN_THRESHOLD 一致）：只需要「回到顶部」。
  • 中间：两个方向都成立 —— 各方案的处理方式不同，见下。
  • 新消息自动贴底时（pinned），「回到底部」自动消失，别跟自动滚动抢。
  • 出现 / 消失：opacity + 4px 位移，150ms；prefers-reduced-motion 时只做透明度。

已定 · 方案 A（按用户反馈改过一处）

  • 中间按「回到底部」，不是「回到顶部」—— 底部才是最新内容，这个方向用得更多。
  • 于是「回到顶部」落在已经在底部的时候：那时「回到底部」是空动作，按钮翻过来正好。
  • 隐含结果：只要内容超过一屏，按钮几乎常在；隐藏态只剩「不满一屏」一种。
  • 图标用箭头 + 横线（到顶 / 到底），跟发送那颗光箭头区分开，别在同一个角落出现两个 ↑。
方案 A · 推荐

列内右下角，单键换向

一个 32px 圆钮钉在内容列右下角（距输入卡 12px、距列右边界 16px）。位置永远不动，只有图标和提示在换：顶部时是 ↓，离开顶部后变 ↑，滚到底部淡出。 只占一个洞，不会有「两个按钮谁在上面」的纠结。代价是图标含义要读一眼 —— 靠 title / aria-label 补足，悬停时显示「回到顶部 / 回到底部」。

方案 B

列内右下角，双键竖排

同一个角落放两个 32px 圆钮，间距 8px。顶部只留下面那颗 ↓；中间两颗都在；底部只留上面那颗 ↑，再到底部整组淡出。 好处是不用认图标方向，箭头永远指向上 / 下两个固定位置。代价是中间态占竖高 72px，且下面那颗的存在/消失会让上边那颗跟着上下跳 —— 要把容器高度固定住才不会动。

方案 C

列外贴边，单键换向

跟 A 同一套逻辑，但把按钮放到内容列外面（列右边界 + 12px），彻底不压正文，读长回答时不会被圆钮挡住半个字。 这块留白在窗口 1440、检视器展开时正好 50px；检视器收起后留白变宽，按钮跟着列边走，仍然贴在内容旁边。 代价是主区窄于约 800px 时留白不够 44px，按钮会贴到面板分隔线上，得退回 A 的位置（用容器查询或 820px 断点切换）。

方案 D

输入卡上方居中，胶囊

位置以输入卡为锚：浮在输入卡上沿 8px、水平居中的一颗胶囊，带文字（「回到底部」「回到顶部」）。 这是 ChatGPT 那种「jump to latest」的做法，方向自解释、不用猜图标，而且正好落在你输入时视线所在的位置。 代价是横向居中会压住正文最后一行的一部分，滚动停住时容易误挡。

按钮规格（四个方案共用）

尺寸圆钮 32×32，图标 15px、1.8 描边；胶囊高 28，字号 11.5
配色底 --raised，描边 --hairline，图标 --fg-2，阴影 --sh-md；悬停底色 --sunken
动效150ms opacity + 4px 位移；滚动用 scrollTo({ behavior: 'smooth' })
无障碍aria-label 写全「回到顶部 / 回到底部」，title 同文案；按钮之间不抢 Tab 焦点（隐藏即 tabIndex=-1）

实现备注

现有 useAutoScroll 已经知道「是否贴底」（pinnedRef），但目前只存在 ref 里、不触发渲染。 要出按钮得把它提成 state，顺便加一个 atTop：同一个 scroll 监听里算 scrollTop ≤ 8， 再暴露 scrollToTop() / scrollToBottom() 两个函数即可，DOM 结构不用动。

我的建议

A：改动最小、位置最稳，一个按钮一套状态机，不会有间距和跳动问题。先做 A，不够用再说。

C 是最不打扰阅读的，但要处理窄窗口（主区 < 800px）时退化成 A 的规则，多一层响应式分支。

B / D 我不太推荐：B 的中间态两个按钮竖着占 72px，还会因为条件渲染上下跳；D 的胶囊会压住正文最后一行，且和输入卡抢注意力。

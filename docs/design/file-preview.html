文件夹文件预览 · 设计稿

文件树 + 文件标签 + 六种预览

参考图（docs/design/3.png）是一个完整的文件浏览器：左侧文件树、右侧内容、 顶部一排文件标签。要在这里落地，绕不开一个问题 —— 它放在窗口的哪一块。

现状是：主区永远是对话（上一轮定的），导航项（看板/记忆/代码/终端/Git/Agent） 在右侧面板里打开，那个面板最小 300、没有上限。 文件预览是一整套界面，塞哪儿都不太自然 —— 这是这份稿子要解决的第一个问题。

参考图里看到的东西

  • 文件标签栏：顶部一行，settings.json × / link-pi-types.mjs × / pi-会话使用指南.md × / ＋。每个带文件类型图标。
  • 文件树：项目名 + 搜索框（「筛选文件」）+ 树。文件夹用展开箭头，文件用类型图标 （{} 是 JSON）。隐藏文件（.git .DS_Store）照样列。
  • 内容区顶部：文件名 + 三个操作（源码视图 </>、复制、更多）。
  • 内容区：这份 md 渲染成了标题、段落、行内代码（灰底）、代码块（灰底框）。

一 · 放哪儿：三个方案

A 放右侧面板（拉宽）、B 占主区（对话切走）、C 主区分屏（对话和文件并排）。

A

放在右侧面板里，点「代码」导航项打开

右侧面板本来就是放「其他视图」的地方。点「代码」→ 面板里再分两栏： 左边文件树 200px、右边内容剩下。面板默认 300 太窄，所以点开「代码」时 自动把面板拉到 700px（面板没有上限，现在就能拉）。

二 · 三个方案比

方案对话能否同时看文件内容宽度改动范围跟参考图的接近度
A 右侧面板能（被挤到 160px）约 460px小低
B 文件也是标签（推荐）能（切标签）约 700px大（标签栏要支持两种）高
C 主区分屏能（并排）约 470px大中

推荐：B

  1. 文件内容需要宽度。代码和 md 都要横向空间，A 的 460px、C 的 470px 都在勉强。
  2. 对话不会消失。会话标签一直在标签栏里，按一下就回来 —— 比「被挤到 160px」好。
  3. 跟参考图一致。参考图就是「标签栏 + 文件树 + 内容」占满主区。

B 的代价是标签栏要同时支持两种标签。但这正好是「标签栏从会话标签升级成工作区标签」—— 一次改到位，以后加别的标签类型（比如终端、看板）也是同一条路。

选 B 要推翻一条已定的决策。 「主区永远是对话」是上一轮定的（导航项只在右侧面板打开）。选 B 之后要改成 「标签栏里始终有对话」 —— 语义上还守住了「对话随时可用」，但主区不再专属对话。 这条要你明确点头。

三 · 文件树怎么画

项做法依据
根目录当前活动标签的 cwd文件属于项目，而项目由标签带进来
加载方式懒加载：只读展开的那一层node_modules 可能有几万个文件，一次读完会卡死
排序文件夹在前、按名字；文件在后、按名字跟 VS Code、Finder 一致
隐藏文件照常显示（.git .DS_Store）参考图里就有，而且配置类文件常以点开头
搜索输入即筛选已加载的节点；未展开的目录不参与全局搜索要扫盘，那是另一件事
图标按扩展名给 {} </> ◇ 之类的纯文字标记不引入图标库，跟现有 icons.tsx 的线条风格保持一致
忽略规则读 .gitignore，命中的置灰但仍显示不隐藏 —— 用户可能就是想看 node_modules 里的某个文件

四 · 六种预览，按扩展名分派

类型扩展名怎么渲染难点
Markdown.md .markdown复用现有的 conversation/Markdown.tsx它只支持标题/加粗/斜体/行内代码/代码块/列表/表格/引用/分隔线。图片、链接、脚注都不支持
图片.png .jpg .gif .webp .svg<img>，从主进程读成 data URL 或自定义协议大图要限制；SVG 可能带脚本，要走沙箱
HTML.html .htm<iframe sandbox="allow-scripts">PLAN.md D3 已定不加 allow-same-origin
代码其余已知扩展名（.ts .js .py .css .json …）等宽 + 行号 + 语法高亮要引入高亮库，现在一个都没有
纯文本其余一切等宽 + 行号，不高亮二进制文件要检测并拒绝（给一句「这是二进制文件」）
PDF.pdf先不做，归到纯文本的「不支持」要额外的渲染器

五 · 语法高亮：要引入一个库

现在项目里只有 React、Zustand、zod，没有任何高亮库。这是文件预览唯一的硬依赖。

选型优点代价
ShikiVS Code 同一套语法和主题，质量最好；输出纯 HTML，不需要运行时体积大（每语言一个 grammar）；首次加载要异步初始化
Prism轻，按需加载语言，主题多语法质量不如 Shiki，尤其 TSX / Vue 这类
highlight.js最轻，能自动检测语言同上；自动检测在短文件上经常猜错
先不做零依赖代码只有等宽，看起来像纯文本

PLAN.md D3 当初选的是 Shiki，但因为「依赖安装没获授权」一直没装，markdown 也是手写的子集。 这次要装的话得先确认能装。

六 · 安全与性能

风险对策
路径越界所有读文件请求在主进程校验：解析后必须在活动标签的 cwd 之内。 拒绝 ../、符号链接指向外面、绝对路径
HTML 里的脚本iframe sandbox="allow-scripts"，不加 allow-same-origin（D3）
大文件超过阈值（比如 2MB）不渲染内容，给一句「文件太大（12MB），不预览」+ 一个「仍要打开」
大目录懒加载 + 一层的条目数上限（比如 5000），超了给一句提示
二进制文件读前 8KB 检测 NUL 字节，命中就当二进制，不渲染
文件被外部改动跟标签的 stale 同一套思路：焦点回来时比对 mtime，变了就提示「文件已更新，重新加载」

#问题我的倾向

5文件树放左侧栏，还是放在主区里（如参考图）？放主区里 —— 左侧栏现在是项目/会话列表，塞不下两棵树
6md 预览复用现有的手写渲染器吗？复用。它支持的那几种格式覆盖了大部分 README

八 · 这一稿不做

项为什么
编辑文件这是「预览」，不是编辑器。要编辑是另一个量级的任务（撤销、保存、冲突）
全局文件搜索（跨目录内容搜索）要扫盘 + 索引，是独立功能
Git 状态标记（文件树里显示 M / A / ?）要读 git，而且 Git 面板已经有了
PDF / 视频 / 音频预览先归到「不支持」，看需求再加
文件树拖拽移动 / 重命名写操作，跟「预览」无关
图片缩放 / 拖拽平移第一版先按容器宽度等比缩放

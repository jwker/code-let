一轮对话里的主次 · 局部方案稿

最终答案要压过过程

这份稿只处理普通模式里一轮对话内部的主次关系：过程叙述、工具行、最终答案这三样东西怎么排。 正文的 markdown 格式、工具行的交互、元信息行（复制 / token / 用时）的样式都不在范围内 —— 元信息行已经按轮挂在末尾，它天然属于答案，这次不动它。

四个方案共用同一轮对话做上下文，方便横向比较。每个方案后面写它适合什么、代价是什么、以及要动哪一层。

先摆事实

  • 现在一轮里的三种内容用同一套排版：过程叙述和最终答案都是 14.5px / 行高 1.9 / fg-1，字号、字重、颜色三项完全一致，读者没有任何线索能分出哪句是结论。
  • 真实会话里过程远比答案多。量过一段 15 段正文的轮次，只有最后一段是答案， 前 14 段都是「我先读一下…」「改成按游标增量…」这类过程话。
  • 读者要的是最后那段，但要先扫过前面全部。轮次越长，这个代价越大 —— 这也是「回答不突出」的直接原因，不是颜色不够重，而是主次没有分层。
  • 工具行本来就已经弱化了（11.5px / fg-2 / 带状态圆点）， 所以真正缺的是过程叙述和最终答案之间的落差，不是工具行。

这份稿里的三个词

过程
一轮里除最终答案以外的助手正文，以及它们之间调用的工具行。
最终答案
这一轮最后一段有正文的助手消息。判断规则已经定了：取最后一段非空正文。
视觉重量
字号、字重、颜色、缩进、底色这几个量的组合。下文说「降一级」就是指这五项里降一档。

四个方案放在一起比

按「答案有多容易扫到」「过程是否还完整可读」「长轮次里的表现」「要动多少东西」四轴排。

方案答案突出度过程可读性长轮次改动量
A 字号分级弱（1.5px 落差）好会变淡但仍旧长小
B 过程收纳最强要点开最好中
C 装订线强（结构分层）好好小
D 底色分带中好页面变碎小

推荐：C 的骨架 + A 的字号

过程缩进 12px、左侧 2px 竖线、字号 13px、颜色 fg-2、行高 1.7； 答案顶格、14.5px、fg-1、行高 1.9、不加任何装饰。 也就是把 C 和 A 叠起来用 —— 结构给主次，字号补足落差。

不选 B 作为默认形态的理由：它把过程藏起来，改动最大，还要新增折叠状态与「这一轮几步」的统计。 但它确实是长轮次的最优解，建议留作第二期的一个开关（「过程默认折起」）， 而不是这一轮的默认行为。

不选 D 的理由和上次否掉元信息胶囊一样：每轮挂一块灰底，长会话里页面会碎。 而且暗色下那两级底色只差 1.06:1，边界本来就要靠圆角撑，收益不划算。

这一轮不做

项为什么
答案加边框 / 卡片 / 底色会给正文再加一层容器，长答案里滚动成本变高；靠「过程弱化」就能让答案显出来，不必再加重答案。
过程默认折起就是上面的 B，留作二期开关。这一轮先不改变「默认看得到过程」这个前提。
按内容判断哪句是结论判断规则已经定了：一轮最后一段非空正文。不做语义分析，那条路不可靠也不可测。
thinking / 思考块显示它不是这一轮的内容流，属于另一件事。
改终端模式普通模式优先（D14）。终端那档的排版这次不动。

怎么算做对了

拿一段真实会话（至少三轮、每轮五段以上过程）逐条看。

#标准
1每一轮里，最终答案能在不看完全文的情况下被认出来 —— 眼睛先落在答案上。
2过程仍然完整可读，不需要点任何东西就能看到工具跑了什么。
3元信息行（复制 / token / 用时）在视觉上属于答案，不属于过程。
4主区被压到 160px 时不出现横向滚动条，缩进与竖线跟着收。
5亮暗两套主题下，过程与答案的落差都成立（暗色里过程不能糊成一片）。
6过程里的列表、代码块、表格在缩进之后不错位。

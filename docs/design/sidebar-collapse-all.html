侧栏 · 全部收起 / 全部展开

侧栏里按项目分组列全部会话，组头左边那个三角能收起一个项目。 这里要的是一次收放所有：38 个会话全摊着要滚很久，全部收起之后只剩 9 行项目名。 四个方案都跟「打开项目」放在一起考虑 —— 那一行现在是侧栏唯一的操作入口，多一件东西就得重新分配这一行。 图里每个框是侧栏的 1:1 裁切（宽 264），只有头部和两个项目组。

前提变了 · 本稿还剩什么用

  • 头部不再放按钮了：侧栏头部改成「项目」（标题）+ 一颗 sliders， 所有动作进浮层（见 侧栏 · 头部操作区）。 所以本稿里的 A / B / D 三个位置方案作废 —— 「收起全部」不再是一个浮在外面的按钮。
  • 本稿剩下的两件事仍然要定：
    ① 它在浮层里长什么样：一行文字（收起全部项目 / 展开全部项目）还是带图标；
    ② 图标/文案什么时候换向（部分收起这个中间态）。
  • 推荐落在浮层里的第二组：动作项（打开项目… / 收起全部项目）在上， 带当前值的设置项（对话筛选：全部 ›）在下，分隔线隔开。

四个方案共用的规则

  • 折叠粒度 = 项目组：就是组头左边那个三角。组内的「今天 / 昨天 / 更早」不管，收起组时一起收掉。
  • 状态不用新存：现有的 codelet:sidebar-collapsed-projects 存的就是一组项目路径。 「全部收起」= 把清单里所有项目加进去，「全部展开」= 清空。
  • 按钮图标随状态换向（约定一）： 全都展开时显示「全部收起」（双上箭头 ⌃⌃），有任何一个组收着时显示「全部展开」（双下箭头 ⌄⌄）。 换句话说，按钮显示的是点下去会做什么。
  • 另一种约定（二）：有组展开着就显示「全部收起」。 跟约定一差在部分收起的中间态 —— 两个约定给出的动作正好相反，图标会来回跳。 选一就得选死，别让用户靠试。
  • 双箭头是刻意的：组头用单三角（▼/▶，说的是这一组的状态）， 全局按钮用双箭头（说的是对所有组做的动作），两个不混。
  • 空态：一个项目都没有时按钮不显示（跟「还没有对话」那段提示一起藏）。
  • 不做动画：组收起现在是条件渲染、瞬间消失，全收起也瞬间消失 —— 高度动画在 9 个组同时收时会很难看。
  • 不做快捷键：这个动作低频，占一个全局键位不值。真要加，⌘⌥C 收起 / ⌘⌥E 展开。
方案 A · 推荐

头部行右侧一个图标钮

「打开项目」改成 flex-1（不再占满整行），右边空出一个 28×28 的位置放图标钮。 位置永远不动，只有图标在换：全展开时是 ⌃⌃（全部收起），有组收着时是 ⌄⌄（全部展开）。 这一行从此是侧栏的操作行：左边管加项目，右边管列表怎么摆 —— 两件都是「对这个列表做什么」的事。 代价是图标含义要读一眼，靠 title / aria-label 补足。

方案 B

头部行右侧一个文字钮

同一个位置，但放文字：「收起全部」/「展开全部」。不用猜图标，看到字就知道点下去会怎样。 264px 的侧栏放得下（两个按钮加起来约 170px），侧栏拖到最窄 200px 也还剩 30px。 代价是这一行从「一个按钮」变成「两个按钮」：左边那个带图标、是侧栏唯一的常驻主操作， 右边这个是纯文字的次操作 —— 权重不对等，看起来像两个同级按钮；而且文字会随状态变，宽度一变整行会轻微抖动。

方案 C

并进「打开项目」的下拉菜单

头部一行还是只有一个按钮，但点开是菜单：打开项目… / 分隔线 / 全部收起（随状态换向）。 头部保持最干净，改动最小（打开项目 不用改宽度）。 代价有两层：一是多一次点击，二是把两件不同类的事塞进一个菜单 —— 「打开项目」是加一个项目，「全部收起」是改列表怎么摆，一个是内容，一个是视图状态。 而且「打开项目」现在是个直接动作（点一下就开），变成菜单入口之后要多走一步。

方案 D

单独一行列表工具条

头部一行只留「打开项目」（不动它），下面另起一行工具条：左边写「9 个项目 · 38 个会话」，右边是图标钮。 语义最清楚：打开项目管「有哪些项目」，工具条管「这个列表怎么摆」，两件事各占一行，谁也不挤谁。 顺手还能把会话总数放回侧栏（之前定的「总数没有位置放」，这里就是那个位置）。 代价是侧栏白占一行 30px，而总数跟组头的会话数重复（各组加起来就是总数）， 跟之前那个决定是反的；侧栏本来就在 264×很满的尺寸里挤。

规格（四个方案共用）

按钮28×28 圆角 8 的图标钮（方案 B 是 28 高文字钮），图标 15px、1.8 描边、currentColor
配色默认 --fg-3，悬停底 --sunken、字变 --fg-1；不抢「打开项目」的注意力
位置跟「打开项目」同一行（方案 A / B）或下一行（方案 D）；不跟着列表内容滚动 —— 它在滚动区外面
无障碍aria-label 写全「收起全部项目」/「展开全部项目」，title 同文案；aria-expanded 反映「有没有组收着」
状态存储沿用 codelet:sidebar-collapsed-projects，不新增键

实现备注

Sidebar.tsx 里 collapsed 已经是一个 Set<string>， 存的是项目路径。全部收起就是 setCollapsed(new Set(projects.map(p => p.path)))， 全部展开就是 setCollapsed(new Set())，各自调一次 saveCollapsed。 项目清单位于 snapshot.projects，按钮的启用与否、图标朝哪，都从它和 collapsed 现算，不用另存状态。

「打开项目」现在是 w-full。方案 A / B 要把它改成 flex-1，右侧才能腾出位置； 方案 C / D 不动它的 DOM。

我的建议

A：一行放两件事，各占一头，位置永远不动；改动只是「打开项目」让出 28px。 「全部收起 / 全部展开」这个动作本来就低频，图标 + title 足够说清楚， 跟对话区滚动按钮用的是同一套「位置不动、图标换向」的逻辑，一致。

D 是语义最干净的，但代价是白占一行，还把之前定掉的「总数不放侧栏」翻了过来 —— 要么接受总数回来，要么那行左边空着（那就退化成 A 了）。

B 我不太推荐：文字钮跟带图标的「打开项目」并排，两个按钮的权重不对等，文字变长变短还会让整行轻微抖。 C 是「最不打扰」的那个，但收放是高频到值得一按的动作（38 条会话摊着确实要滚很久），藏进菜单里等于把刚需降级。

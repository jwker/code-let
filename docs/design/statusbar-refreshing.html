状态栏的「刷新中」标识

什么时候显示「刷新中」

刷新时机有四个来源（Pi 事件、用户操作、窗口焦点、启动），但只有一种刷新**有可感知的耗时**： 重读会话列表（refreshConversations）。实测 4 个项目 21 个会话约 180ms。 其余几个（readSession 读 runtime 内存）是微秒级，不值得显示。

所以这个标识只为「重读会话列表」而做。下面比的是显示什么形态、放哪、 以及什么时候出现和消失 —— 最后一条最容易做错。

先摆事实

  • 耗时：一次重读约 180ms（4 个项目 21 个会话）。项目多、会话多会更久。
  • 频率：发消息后（去抖 100ms）、切窗口（离开 ≥3 秒）、开关项目时各触发一次。
  • 主进程还是渲染进程：读盘在主进程，所以标识要由主进程把「正在刷新」这个状态推下来。
  • 180ms 会闪：一个东西出现 180ms 再消失，人眼会看到一次「抖」。所以时序比形态更重要。

一 · 三个形态

都放在状态栏右侧，跟「普通 · events · Pi 就绪」那一串并列。

A · 推荐

转圈 + 「刷新中」

一个小转圈加两个字。最明确 —— 不用猜那个转圈是什么意思。

Codeletsession 01a18b42 刷新中 普通events 214Pi 就绪
Codeletsession 01a18b42 普通events 214Pi 就绪

上面是刷新中，下面是平时（标识完全不占位）

好处：一眼看懂，不用学。
代价：占宽 —— 「刷新中」三个字约 36px，加上转圈和间距约 50px。 状态栏右边已经有四项，窄窗口时会挤。
B

只有转圈

一个 10px 的转圈，没有文字。最省空间。

Codeletsession 01a18b42 普通events 214Pi 就绪
好处：只占 10px，几乎不挤。
代价：不说明在刷什么。状态栏里出现一个转圈，用户会猜「是网络在转？还是模型在转？」。
C

状态栏顶部一条细线（不走马灯）

不在右侧加东西，而是在状态栏上沿画一条 2px 的线，刷新时线变成一条滑动的进度条。

Codeletsession 01a18b42 普通events 214Pi 就绪
好处：完全不占文字空间，也不打断状态栏那一行的读法。
代价：太淡 —— 2px 的线在窗口底部，眼睛不一定扫得到； 而且它看起来像「页面加载进度」，容易误会成更重的事情。

二 · 时序：什么时候出现、什么时候消失

这一节比形态重要。180ms 的刷新如果每次都闪一下，比不显示还烦。

方案 1（立即显示、立即消失）—— 会闪 ┌─ 刷新开始 │ ▼ 出现 │ ████ 180ms │ ▼ 消失 └─────────────────────────────► 时间 问题：180ms 的东西出现又消失，看起来像「抖了一下」 方案 2（延迟 200ms 才出现）—— 快的时候完全不显示 ┌─ 刷新开始 │ │ ▼ 200ms 还没完 → 出现 │ ████ 剩下的时间 │ ▼ 消失 └─────────────────────────────► 时间 180ms 的刷新：什么都不显示（因为 200ms 前就结束了） 2 秒的刷新：从 200ms 开始显示，一直到最后 方案 3（延迟 200ms + 最短显示 500ms）—— 推荐 ┌─ 刷新开始 │ │ ▼ 200ms 还没完 → 出现 │ ████████ 至少 500ms │ ▼ 消失 └─────────────────────────────► 时间 快的刷新：不显示 慢的刷新：显示了就至少停 500ms，不会闪

推荐：形态 A + 时序 3

  1. 形态选 A（转圈 + 「刷新中」） —— 状态栏是给「当前在发生什么」用的， 一个不知道在转什么的转圈反而是噪音。50px 的宽度在 1440 窗口里不成问题。
  2. 时序用「延迟 200ms + 最短 500ms」 —— 这是「不闪」的关键：180ms 的刷新根本不显示；真慢了才显示，显示了就停够时间。
  3. 位置在右侧、跟状态并列 —— 不占左边的身份区（Codelet / session）， 右边那一串本来就是「现在什么状态」。

如果以后觉得 50px 太宽，降到形态 B（只有转圈）+ 一个 title 说明在刷什么。

三个要你定的：
  1. 只显示「会话列表刷新」，还是也显示「标签重载」？ 重载一个标签（reloadTab）要重建 runtime，耗时比 180ms 长得多 —— 那个更值得显示。可以两个共用同一个标识。
  2. 延迟 200ms 这个门槛 —— 如果实际用下来 180ms 的刷新经常被感知到卡， 说明门槛该调低（比如 120ms）。
  3. 要不要区分「正在刷新」和「刷新完了」 —— 比如完了之后闪一下「已更新」再消失。 我倾向不要：状态栏不该变成通知中心。

三 · 怎么实现（技术要点）

不是纯前端的事 —— 刷新的耗时在主进程，状态要从主进程推下来。

在哪做什么
contract/index.tsHostSnapshot 加 refreshing: boolean
host/main/state.tsrefreshConversations 开始置真、结束置假，各 push() 一次
host/renderer/src/shell/StatusBar.tsx读 snapshot.refreshing，按延迟/最短显示规则渲染
host/renderer/src/shell/refreshIndicator.ts（新）延迟与最短显示的纯逻辑，好测

延迟和最短显示放在渲染进程，不放主进程：主进程只管「我正在读盘」这个事实， 什么时候该显示给人看是 UI 的事。

四 · 怎么算做对了

#标准
1发一条消息（触发 180ms 的刷新）→ 状态栏不出现「刷新中」（太快，不闪）
2项目很多、刷新超过 200ms → 出现「刷新中」，刷完消失
3刷新在 250ms 结束 → 标识至少停留 500ms 才消失，不闪
4标识出现时，状态栏右侧其他项不换行、不挤掉
5窄窗口（960px）下也不溢出
6亮暗两套主题下转圈和文字都看得清

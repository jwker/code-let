# 会话树画成一条主干加窄缝的 git 分支图，正文不缩进

树弹窗里一行一轮：提问是正文，回答压成下方一行最多 20 字的暗色小字。图形是 `git log --graph`
沿水平中轴上下翻转的样子 —— 左边一条主干竖线从第一轮拉到当前叶，别的支线从分叉点拐进主干右边
18px 一条的窄缝，各占一条竖线、各用一种颜色（紫 / 琥珀 / 青 / 玫瑰，循环）。正文全部对齐在同一列，
不随支线缩进；选中只给正文区域上背景，图形区不上色。

支线编号与颜色在整棵树加载时算一次（原型里叫 `BRANCH_NO`），跟当前叶无关：切支线、截断前后，同一条支线
还是同一个「支线 N」、同一种颜色。

## Considered Options

- **条目级缩进树**（pi `/tree` 的画法）：一行一个条目，每层缩进 22px，用户消息实心点、助手回复空心圈。
  结构看得见，但三条支线就有三层缩进，正文被推到右边；助手回复单独占行，六轮要十几行。
  这是工单 04 最早的一版验收项，已经在原型里废弃。
- **一条支线一列、正文跟着列走**：每条支线分一列宽度，正文变窄；切支线时正文横向跳位，读起来像换了一页。
- **主干 + 窄缝**（采用）：线只占 18px 一条，正文位置固定；切支线只换哪条线在上色、哪个点是黑的。

## Consequences

- 宿主侧契约保持条目级（`SessionTreeNode`），一行一轮由渲染层的纯函数 `treeToRows` 合并，规则写在
  `.scratch/conversation-tree/spec.md` 的「渲染层：树弹窗 · 合并规则」。两个函数分开测。
- **活动路径上的孩子必须接在同一条 lane 上，与它是第几个孩子无关。** 只认「第一个孩子」会在切支线时
  画错：当前叶如果不是第一个孩子，叶就挂在自己的彩色 lane 上，而主干仍留在最左往下画到叶的行高，
  两条线一起冒充上下文。原型里出现过这个状态，已修。
- 颜色只有四种，超过四条支线开始重复；重复时靠「支线 N」标签区分，不能靠颜色。
- 图形区宽度随本屏支线数变化，所以要设最小宽 80px（三条支线的位置），否则状态一变正文就横向跳动。
- 一条 lane 要等它那条线结束（最后一行在那行之上）才能借给新支线，否则两条线画在同一个 x 上、
  后者盖掉前者。
- 选中行不给图形区上色：行背景会盖住穿过这一行的支线。选中的那一轮靠自己的点加一圈环标出
  （活动支线黑环，别的支线用自己的颜色）。
- 颜色取值、18px 与 80px 这些尺寸归原型和视觉稿，e2e 只断言状态（哪条是主干、叶在哪、标签在不在、
  正文是否同一列），不做像素比对。
